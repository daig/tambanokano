# A1 — Runtime kernel & memory model (deep-dive report)

**1. Functional scope.** This subsystem is the runtime heart: the dual representation of expressions (compile-time `Term` trees vs. runtime hash-consed `DagNode` DAGs), the garbage-collected node arena, substitutions, the rewriting context, the equational `reduce` loop, the rule-rewriting traversals (`reduce`/`rewrite`/`frewrite`), the compiled stack-machine path, sort caching on dag nodes, and evaluation control: operator `strat` strategies (manual §4.4.7, 1862-1932), `memo` (§4.4.8, 1934-1972), `frozen` (§4.4.9, 1974-1998), and the `iter`/successor theory's big-integer stacked numbers (§4.4.2, 1626-1640). It implements the term sharing/canonical-form machinery described in §4.7 (2234-2306) and the dag-sharing note at 2480-2490.

**2. Architecture in C++.** *Duality.* `Term` (`Interface/term.hh:37`) is a parse-time tree carrying static analysis (occurs sets, eager/stable/honors-ground flags `term.hh:247-283`); `term2Dag`/`dagify` (`term.hh:398-416`) lowers it to a `DagNode`. `DagNode` (`Interface/dagNode.hh:31`) is the runtime node. Both dispatch through deep C++ **virtual hierarchies** — each theory subclasses `Term`, `DagNode`, `Symbol`, `LhsAutomaton`, `RhsAutomaton`, `Instruction` (`dagNode.hh:114-122` lists the pure virtuals: `markArguments`, `copyWithReplacement`, `makeClone`, `getHashValue`…).

*Memory.* A `DagNode` is exactly one `MemoryCell` (`Core/memoryCell.hh:32-35`), which multiply-inherits `MemoryBlock` (5 filler words, `memoryBlock.hh:65`) and `MemoryInfo` (one flags byte + spare byte + `halfWord`, `memoryInfo.hh:94-97`). The node's first word is a `topSymbol`/`copyPointer` **union** (`dagNode.hh:254-264`), its second the vtable pointer; the cached sort index lives in `MemoryInfo::halfWord` (`dagNode.hh:341-351`), per-node booleans in the flag byte (`dagNode.hh:234-248`: REDUCED, COPIED, GROUND, HASH_VALID…), and a theory-specific `byte`. Nodes are bump-allocated from fixed 5460-node arenas (`memoryCell.hh:79`, `allocateMemoryCell` `memoryCell.hh:199-228`) plus variable-size *buckets* for oversized payloads. GC is a **non-moving mark-and-lazy-sweep collector** (`memoryCell.cc:327-411`): roots are an intrusive doubly-linked list of `RootContainer`s (`rootContainer.hh:29-81`); `DagNode::mark` is an iterative marker with tail-call elision via `markArguments` (`dagNode.hh:576-597`); `collectGarbage` tidies/sweeps, recomputes a "slop factor" target, and pre-allocates arenas (`memoryCell.cc:386-396`). Collection happens only at safe points (`okToCollectGarbage`, `memoryCell.hh:140-145`). `DagRoot` (`dagRoot.hh`) is a smart root pointer; three placement-`new` overloads incl. **destructive in-place rewrite** `new(size, DagNode* old)` (`dagNode.hh:398-410`, paired with `overwriteWithClone`) so a replacement appears on all DAG paths.

*Hash-consing.* `HashConsSet` (`hashConsSet.hh:31`) interns canonical nodes via `Symbol::makeCanonical`/`makeCanonicalCopy` (`symbol.hh:179-183`, `hashConsSet.cc:43-94`); `MemoMap` (`memoMap.hh:31`) layers from-dag→to-dag memoization on it.

*Control.* `Symbol` (`Interface/symbol.hh:42-52`) is a **god-class** multiply-inheriting nine mix-ins (`SortTable`, `EquationTable`, `RuleTable`, `Strategy`, `MemoTable`, `EqRewriter`…). The hot equational loop `DagNode::reduce` (`dagNode.hh:562-574`) repeatedly calls `topSymbol->eqRewrite` — notably a **C-style function pointer** (`eqRewriter.hh:29-47`), a deliberate move off virtual dispatch. `RewritingContext` (`rewritingContext.hh:40`) *is-a* `Substitution` (so the match scratchpad is reused) plus a GC root; rule rewriting (`run.cc:23-160`: `ruleRewrite`, `fairRewrite`, `descend`/`ascend`/`doRewriting`) walks a `redexStack` with a `staleMarker`, rebuilding the spine by path-copying via `copyWithReplacement` (`rewritingContext.cc:212-261`). `Substitution` is a `Vector<DagNode*>` split into fragile (GC-protected, copied) and construction slots (`substitution.hh:41-65`). The optional compiled path (`stackMachine.hh/.cc`) `mmap`s a ~1 GB frame stack (`stackMachine.cc:42`) and runs `Instruction`s (opcode + virtual `execute`, `instruction.hh:31-73`) produced by `StackMachineRhsCompiler`. `Strategy` stores the strat list, eager/evaluated/frozen `NatSet`s (`strategy.hh:30-55`); `S_DagNode` holds a GMP `mpz_class` count + arg (`S_DagNode.hh:31-36`).

**3. Rust migration.**
- **DagNode hierarchy + raw-pointer DAG → RETHINK.** Replace the virtual class tree and `MemoryCell` punning with an **index-arena** (`slotmap`/`id-arena`): `DagNode` becomes an `enum { Free{sym,args}, Acu{…}, Var{idx}, S{count: BigInt, arg}, … }` keyed by `DagId(u32)`. *Rationale:* indices give cheap shared aliasing without `unsafe`/raw pointers and make GC roots trivially trackable.
- **Theory dispatch → enum-dispatch** over the fixed built-in theory set (free/ACU/AU/CUI/S/NA/variable), not `dyn Trait`. *Rationale:* no vtable on the hottest data structure; theories are closed.
- **Arena + mark-sweep GC → ADAPT.** PORT the lazy-sweep/slop-target algorithm but over a `Vec`-backed slot arena with a mark bitset; roots held explicitly by the engine, `DagRoot` becomes an RAII root guard (register on construct, drop = unregister). *Rationale:* refcounting (`Rc`) can't match Maude's bump-allocate throughput and breaks under in-place mutation. (Acyclic DAGs mean cycles aren't the issue; aliasing+mutation is.)
- **In-place destructive rewrite/`overwriteWithClone` → ADAPT (clean fit):** mutate `arena[id]` in place — the id-arena gives exactly the all-paths-update semantics without the union/placement-`new` trick.
- **`reduce`/rule traversal, path-copying, staleMarker → PORT** logically; `eqRewrite` fn-pointer → a method on the symbol enum or an `fn` field.
- **Term duality → PORT** (owned `Term` tree compiled once → arena DAG).
- **Substitution → PORT** as `SmallVec<[Option<DagId>; N]>`; **RewritingContext → ADAPT** to composition (embed substitution; pass `&mut Engine`) instead of inheritance.
- **Symbol god-class → RETHINK** into composed structs (sort/equation/rule/strategy/memo tables as fields).
- **Stack machine → ADAPT/defer**: enum instructions + `Vec` frame stack, drop the 1 GB raw arena. **iter numbers → PORT** with `rug`/`num-bigint`. **Hash-cons/memo → PORT** with `hashbrown` keyed by structural hash (`dagNode.hh:727-737`).
- **Does NOT translate:** the `topSymbol`/`copyPointer` union, `MemoryCell` multiple-inheritance layout and bit-packed `MemoryInfo`, placement-`new`, intrusive `RootContainer` list, vtable-pointer assumptions (`dagNode.hh:215` "HACK"), global mutable GC statics.

**4. Hardest parts / risks / open questions.**
- **GC is the #1 risk:** Maude's speed (500K–several M rewrites/s, manual 555) depends on bump-allocation, non-moving lazy sweep, and tuned slop factors. A naive collector regresses perf badly; getting an arena+mark-sweep that matches it is the central engineering problem.
- **Pervasive shared-mutable aliasing:** in-place flag/sort/sort-index mutation on shared DAG nodes is fundamentally borrow-checker-hostile; the id-arena + interior-mutability decision is load-bearing for the whole port.
- **Node size / cache footprint:** the bit-packed cell is a real micro-optimization; Rust enums must stay compact (consider niche-packing sort index/flags).
- **Open:** single global engine vs. re-entrant contexts (current GC is global statics); whether to keep the compiled stack-machine path at all in v1; how memo-table sort-upgrade invariants (`hashConsSet.cc:55-61`) map onto canonical ids.

**5. Proposed Rust module layout (`kernel` crate).**
`dag.rs` (DagNode enum, DagId, flags, cached sort) · `arena.rs` (slot arena + free list) · `gc.rs` (mark-sweep, root set, RootGuard) · `hashcons.rs` · `memo.rs` (MemoMap) · `term.rs` (Term tree + `term2dag`) · `symbol.rs` (Symbol + composed tables, theory tag) · `substitution.rs` · `context.rs` (RewritingContext, `reduce`) · `rewrite.rs` (rule/fair traversal, path-copy) · `eval.rs` (Strategy/frozen/eager) · `stackmachine/{frame,instr,compiler}.rs` (optional). Variable nodes/terms (`variableDagNode.hh`, `variableTerm.hh`) fold into the `Var{index}` enum arm.
