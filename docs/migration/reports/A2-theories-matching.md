# A2 — Equational theories & matching engine (deep-dive report)

### 1. Functional scope
Maude matches and rewrites *modulo* the equational axioms `A` attached to operators (manual §4.4.1, lines 1563–1604): `assoc`, `comm`, `idem`, two-/one-sided `id:`. Each combination is a *theory* with its own term representation, normal form, and dedicated **matching modulo A** algorithm. Key semantics (§4.8, lines 2308–2428): associative subjects are stored **flattened** (`f(u1..un)`, no nested `f`, identities simplified away); a pattern `f(t1,t2)` matches a *maximal* `f`-subterm **with extension** (the matched portion need not be the whole node); collapse theories (`id:`/`idem`) admit true collapse matching where a pattern can match a subject not even built with `f` (manual §20.3.6/20.3.7, lines 11222–11246). Matching is generally **multi-solution** (the `xmatch` example yields 12, lines 2404–2424), so the engine must enumerate. The companion features — RhsAutomaton (replacement construction), coherence/extension, and per-theory unification primitives — round out the subsystem.

### 2. Architecture in C++
The design is a **theory plug-in pattern over virtual base classes** in `Interface/`. Five abstractions are implemented by every theory: `LhsAutomaton::match()` (`lhsAutomaton.hh:39`) returns a bool plus an optional `Subproblem*`; `Subproblem::solve(findFirst, ctx)` (`subproblem.hh:45`) lazily enumerates remaining solutions on backtracking; `RhsAutomaton` builds the instantiated RHS via `construct`/`replace`/`remapIndices` (`rhsAutomaton.hh:34-38`); `ExtensionInfo` records the matched portion for AC/AU/S matching (`extensionInfo.hh:40-42`); `UnificationSubproblem` mirrors this for unification (`unificationSubproblem.hh:34-35`). Matching is **two-phase**: a deterministic `match()` does the cheap forced work and returns a residual `Subproblem` whose `solve()` does multi-solution search. Generic combinators in `Core/` glue per-theory subproblems: `SubproblemSequence` (`subproblemSequence.hh:30`, AND), `SubproblemDisjunction` (OR), plus leaf checks `SortCheckSubproblem`, `EqualitySubproblem`, `ExtensionMatchSubproblem`. Patterns are compiled once: `Term::compileLhs`→ virtual `compileLhs2` (`Interface/term.hh:100,126`) produces the automaton.

**FreeTheory** is the hot path. `FreeSymbol` (`freeSymbol.hh:35`) owns a `FreeNet` **discrimination net** (`freeSymbol.hh:129`). The net is a flattened ternary search tree of `TestNode`s (`freeNet.hh:96-108`) keyed on `(stack-slot, argIndex, symbolIndex)` with `<,=,>` branches, executed by an explicit stack machine in `findRemainderListIndex` (`freeNetExec.hh`) — no recursion, deliberately unrolled for branch prediction. Reaching a leaf yields `FreeRemainder`s (`freeRemainder.hh`), each carrying the non-skeleton work classified into `freeVariables`, `boundVariables`, `groundAliens`, `nonGroundAliens`. `FreeLhsAutomaton::match` (`freeLhsAutomaton.cc:171-291`) walks the free skeleton over a `Vector<DagNode**>` slot stack, binds/checks uncertain & bound variables, compares ground aliens, and recurses into alien sub-automata, accumulating their subproblems. A `Speed` enum (`freeRemainder.hh:39-59`) tags remainders `SUPER_FAST`/`FAST`/`SLOW` and inlines binding without sort checks where provably safe (`freeRemainder.hh:131-249`); `FreePreNet` compiles the abstract net then `semiCompile`s it into the runtime `FreeNet`, with templated per-arity `eqRewrite` entry points (`freeSymbol.hh:107-126`). RHS is a flat `Instruction` list (`freeRhsAutomaton.hh:54-67`).

**ACU_Theory** is the most elaborate. Subjects use a dual representation: flat `ACU_DagNode` with `ArgVec<Pair{dagNode,multiplicity}>` (`ACU_DagNode.hh:38,146`) for small terms, and red-black `ACU_TreeDagNode` (`ACU_TreeDagNode.hh:31`) above a size threshold (`CONVERT_THRESHOLD=8`). Compilation (`ACU_LhsCompiler0.cc:34-74`) first tries cheap **special-case automata** (`ACU_VarLhsAutomaton`, `ACU_GndLhsAutomaton`, `ACU_CollectorLhsAutomaton`, `ACU_NonLinearLhsAutomaton`), else builds a full `ACU_LhsAutomaton`. At match time a `MatchStrategy` (`ACU_LhsAutomaton.hh:36-75`) is chosen — `GROUND_OUT`, `LONE_VARIABLE`, `ALIENS_ONLY`, `GREEDY`, `FULL`. The general path eliminates ground aliens/bound vars, runs a greedy heuristic, and on failure `buildBipartiteGraph` (`ACU_LhsAutomaton.hh:179`) produces an `ACU_Subproblem` (`ACU_Subproblem.hh:33`): a **bipartite graph** of pattern-aliens vs. subject-arguments plus a **Diophantine system** (`DiophantineSystem`, `ACU_Subproblem.hh:108`) over remaining variable multiplicities. `solve()` alternates `solvePatterns` (backtracking edge selection over `currentMultiplicity`) and `solveVariables` (Diophantine enumeration) (`ACU_Subproblem.cc:140-209`). `ACU_LazySubproblem` (`ACU_LazySubproblem.hh:35`) strips one argument at a time from the tree to avoid copying huge subjects. `AssociativeSymbol::Structure` (`associativeSymbol.hh:42-48`: `UNSTRUCTURED/LIMIT_SORT/PURE_SORT`) lets matching bind `f(...)` to a sorted variable without recomputing sorts. **AU/CUI/S/NA** repeat the pattern at lower complexity: AU adds `AU_DequeDagNode`/`AU_Layer` for assoc-only with extension; S handles `iter` stacked successors with `S_ExtensionInfo`; NA is the trivial constant case (`NA_LhsAutomaton.hh`).

### 3. Rust migration
- **Theory dispatch (RETHINK).** Replace the C++ virtual hierarchy with a fixed `enum Theory { Free, ACU, AU, CUI, S, NA }` and **enum-dispatch** for symbols/dagnodes/automata (closed, perf-critical set). Keep narrow `trait LhsAutomaton { fn match(...) -> MatchResult }`, `trait Subproblem { fn solve(&mut self, find_first: bool, ...) -> bool }` as `Box<dyn>` only where heterogeneity is unavoidable (residual subproblems). Rationale: closed theory set ⇒ enums beat vtables; subproblem trees stay dynamic.
- **Two-phase match + lazy backtracking solve (PORT, structurally).** Keep the `match()`→residual-`Subproblem` split, but model `solve(find_first)` as an explicit resumable iterator/coroutine (`Iterator<Item=()>` over a borrowed `&mut Substitution`, or a hand-rolled state enum). Rationale: idiomatic enumeration without the `findFirst` bool protocol.
- **Free discrimination net (PORT).** `Vec<TestNode>` with index links ports directly; the unrolled stack machine becomes a `loop` over `&[TestNode]`. The `DagNode**` slot stack becomes `Vec<&[Node]>` / arena indices. Templated per-arity `eqRewrite` → monomorphized generics or a small match on arity.
- **ACU representations (ADAPT).** `ArgVec<Pair>` → `SmallVec<(NodeId,u32)>`; `ACU_TreeDagNode` → a `BTreeMap`-like or a ported persistent red-black tree (crate `rpds`/`im` for the persistent `ACU_Persistent`/`AU_Persistent` structures). Bipartite+Diophantine solver ports as plain Rust (own integer `DiophantineSystem`); `LocalBinding` diffs → owned `Vec<(VarIndex,NodeId)>`.
- **Does NOT translate:** raw `DagNode**` slot arrays and `friend`-class direct field access (→ arena handles + crate-internal `pub(crate)`); manual `delete` of subproblem/difference chains (→ ownership/`Drop`); the `union` in `FreePreNet::NodeBody` (→ Rust `enum`); `#ifdef DUMP`/`COMPILER` and the C++-codegen `freePreNetFullCompiler` (drop; keep only the semi-compiler). Pointer-tagged normalization-status bits → typed fields.

### 4. Hardest parts / risks
- **Collapse matching** (`id:`/`idem`): infinite equivalence classes, subtle extension cases (manual §20.3.6/7) — `ACU_CollapseMatcher`, `multiwayCollapseMatch` are intricate and easy to get subtly wrong; needs a conformance test suite from `xmatch`.
- **AC multi-solution completeness with extension** under sort constraints + the bipartite/Diophantine interaction; correctness ⇄ performance (greedy fast path vs. full search).
- **Borrow checker vs. the substitution-shared-mutably pattern:** `solve()` mutates a shared `Substitution` while subproblems hold references — likely needs arena indices + interior mutability rather than `&mut` threading.
- **Tree vs. flat representation switch** and persistent structures; getting GC/arena interplay right (coordinate with A1).
- Heuristic strategy selection (`MatchStrategy`) must be re-derived from data, not ported blindly.
